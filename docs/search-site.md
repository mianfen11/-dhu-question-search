# 静态检索网站

网站位于 `web/`，与 `extension/` 完全分离；未改动扩展 1.2.0 或 `tools/question_bank.py`。没有框架、第三方在线字体、分析服务、注册、上传或外部搜索。浏览器只下载本站静态资源和 `question-bank.json`，不访问 aidhu.net 的接口。

## 数据转换与答案规则

```bash
python3 tools/build_search_bank.py /path/to/export.json -o web/question-bank.json
python3 tools/build_search_bank.py /path/to/new-export.json \
  --merge web/question-bank.json -o web/question-bank.json
```

工具复用 `question_bank.unpack/normalize/options_for`，不改变原 Python 导入规则。支持 A～E、标准 options 对象/数组、各类字母答案格式和原站 1/0 判断题。使用 UTF-8/BOM 读取，原子写入；不能覆盖原始导出，`--merge` 明确允许读写同一个网站数据文件。

转换分为以下步骤：

1. 按既有封装格式展开记录，规范化题型、题干、选项和答案。
2. 在**每一条原记录内部**把答案字母映射到该记录的选项全文，绝不借用其他版本的选项顺序。
3. 按“题型 + NFKC/空白规范化后的题干”分组，不靠 question_id 强行覆盖；跨章节保留来源。
4. 比较正确答案的**文字集合**。多选文字顺序无关。选项乱序、答案从 A 改成 B 但正确文字相同，属于同一答案；选项变化仍作为不同保存版本保留。
5. 同题出现不同正确文字集合，标 `conflict`，不生成确定答案。混有无法映射版本则标 `unverified`；已知版本不能掩盖未知版本。既有冲突又有未核实版本时同时保留两个状态信息。
6. 判断题只按可靠的 1/0/布尔/正误表述映射；带含义不明确的 A/B 选项时待核实。缺答案、选项不足、引用不存在选项等均不猜测。

题干及答案比较**不会删掉标点或改写字母大小写**：例如 `3.5` 与 `35`、`mW` 与 `MW` 不会被误合并。搜索归一化与数据去重是两套规则。只有题干明确一致才合并，近义改写、不同标点的题目可能仍分列；这是偏向准确性的保守选择。相同泛化题干（如“以下哪项正确”）的不同答案版本会保守显示冲突，不擅自判定为同一个确定答案。

### 网站数据结构

`schema_version:1`、`format:dhu-search-v1`。每道题包含：

- `id`、`question_type`、`question`。
- `status`：`verified` / `conflict` / `unverified`。
- `answer_texts`：只有已验证且无冲突的组有确定答案。
- `has_unverified`：冲突题也能同时包含待核实记录。
- `variants`：各版本的选项、当前字母、映射文字、原始答案、原选项形式及映射状态/原因。
- 版本 `sources`：文件 basename、记录序号、手册/章节、题目 ID、source、analysis 和解析变体。不复制任意 raw/provenance 对象、未知元数据或认证字段。

若选项对象与 A/B 字段互相矛盾，保留两种可读形式并标待核实；无法识别的任意嵌套对象用无效值标记替代，不把整段原始 JSON 发布到网页。无题干或未知题型的记录也保留为待核实，不伪造题目。

`--merge` 从网站已保存的原选项/答案重算映射后再归并，原有来源和冲突版本保留。相同文件重复导入不会重复增加题目或同版本来源。文件名改变会保留额外来源依据，不增加唯一题数。输出顺序及 ID 稳定，没有“每次更新时间”引起的无意义差异。

统计中的 `input_records` 是本次检查的原始输入条目数，使用 `--merge` 时包括历史归并库的各保存版本；`mapped_answer_records` 是其中能成功映射的条目数，均不等于唯一题数。冲突题/未核实题各按题组计数，两者可以重叠。当前转换返回 0 表示文件成功生成，**不表示没有冲突**；请查看统计和页面警示。结构损坏的整个输入文件会报错退出而不写入，不静默跳过。

浏览器不盲信 report 的收录数量：按实际 questions 数量显示。加载时复核原答案→字母→选项文字、题干分组、状态、候选集合和来源结构；映射受损则显示加载错误，避免把损坏数据当确定答案。

## 本地检索

`search.js` 使用轻量的原生 JS 索引：

- 搜索时 NFKC、大小写、常见标点与空白归一化。
- 多个关键词顺序无关，题干和**各版本选项**都参与；题干全词权重大于选项全词。
- 连续短语优先；中文无空格或有中间遗漏时，按字符二元组匹配。至少需要充分的二元组证据（覆盖率不低于 60%，且至少 2 个二元组），不靠单个常见汉字猜测长短语。
- 每个输入关键词均需满足完整或受限部分匹配，多词共同命中提高得分；按分数及稳定 ID 排序。
- 命中高亮使用原文位置和 DOM text/mark 节点，不拼 HTML。n-gram 是关键词近似检索，不是语义搜索，也不生成答案。

正常检索在模块 Worker 中执行，主线程只在 Worker 不可用时回退同一算法。输入防抖 110ms，中文 IME 组词期间不检索，查询序号丢弃过时响应；输入后先清掉旧结果，避免把上个关键词的答案误认为当前结果。查询最多 200 字符。

每次仅渲染 25 道，点击“显示更多”追加 25 道并将键盘焦点移到新增结果。版本详情在展开时才创建 DOM，避免一条多版本题拖慢初始结果。12,000 条合成记录的索引/检索有自动化性能检查，但不代表无限量数据或所有手机性能保证。

## 使用须知与可访问性

首次进入使用原生 `dialog.showModal()`，不独立跳欢迎页。四项须知、默认未勾选的“不再提示”及确认按钮均可键盘操作；背景 inert、焦点限制在弹窗、关闭恢复到搜索框或“使用说明”。Escape 可关闭但不写偏好。

仅在确认按钮点击时保存勾选选择到 localStorage。勾选后下次不自动打开；不勾选则下次仍提示。手动打开时反映现有偏好，单纯打开或 Escape 不改写。存储被限制时仍可确认并使用搜索，不会抛异常阻止页面。搜索词不持久化、不上传。

页面使用系统中文字体、语义标题、可见键盘焦点、搜索框标签、状态播报及 16px+ 移动输入框。弹窗小屏内部滚动，支持减少动态效果偏好。目标为当前 Chrome 与 Safari 15.4+（原生 dialog/module Worker/Object.hasOwn 等能力）。桌面与移动 Chromium 视口已测，不把视口模拟当作真实 iPhone Safari 验证。
